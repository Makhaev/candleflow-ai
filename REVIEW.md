# Ревью инструмента reserve_material

| Приоритет | Проблема | Исправление |
| --- | --- | --- |
| Критический | Интерполяция кода материала в SQL допускает SQL-инъекцию. | Типизированная схема аргументов и параметризованный запрос через SQLAlchemy. |
| Критический | Инструмент меняет склад сразу, без подтверждения и проверки полномочий. Нет надёжной привязки к пользователю. | Сформировать предложение с владельцем и сроком. На подтверждении заново проверять роль и состояние задания. Кнопка и ассистент используют один сервис. |
| Критический | Два вызова читают один свободный остаток, затем оба его резервируют. При сбое в середине может остаться часть обновлений. | Транзакция, блокировки строк партий в порядке материала, даты и номера, расчёт под блокировкой. Ограничения на количество и резерв в PostgreSQL. |
| Высокий | Резерв нигде не связан с заданием. Повтор запроса добавляет его второй раз. Запуск, отмена, списание и аудит не знают, кому принадлежит материал. | Хранить распределение `задание × партия` с уникальным ключом. Использовать блокировку задания и идемпотентное подтверждение. Записывать аудит в той же транзакции. |
| Высокий | Сортировка по убыванию ID нарушает FIFO, проверка статуса отсутствует. | Выбирать только принятые партии. Сортировать по дате поступления, затем по номеру. |
| Высокий | `float` округляет количество. Пропущенные поля, отрицательные числа, NaN и бесконечность попадают в расчёт. При нарушенном остатке `take` может стать отрицательным. | Валидировать конечный положительный Decimal с ограниченной точностью. PostgreSQL NUMERIC и проверка `0 ≤ reserved ≤ quantity`. |
| Высокий | Ответ всегда обещает полный резерв, даже если часть сырья отсутствует или материал неизвестен. | Возвращать структурированный результат с потребностью, резервом, дефицитом и статусом. Блокировать запуск при дефиците. |
| Средний | Сырые аргументы модели записываются целиком в лог. Они могут включать ФИО и произвольный пользовательский текст. | Писать идентификатор запроса, разрешённое имя инструмента, длительность и код исхода. Журнал изменений с ФИО вести отдельно, с контролем доступа. |
| Средний | `SELECT *`, загрузка всех партий и обновления даже при нулевом резерве увеличивают нагрузку. | Читать нужные поля через индекс, пропускать нулевой резерв, измерять объём выборок на характерных данных. |

Проверил бы принятые и бракованные партии, одинаковые даты, дробный остаток, полный и частичный резерв, два конкурентных запроса, откат после ошибки, повтор подтверждения и попытку вызова от кладовщика.
